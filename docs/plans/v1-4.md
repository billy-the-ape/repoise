Status: complete.
Repository: billy-the-ape/repoise. Depends on: [PR 2 (v1-1.md)](v1-1.md).

## Implemented state

- `crates/repoise-core/src/history.rs`: local history contracts and services.
  `HistoryProvider` (adapter seam), `HistorySet`/`HistoryItem`/`HunkDescriptor`
  records, PR-hint parsing (`#123` boundaries, deduped, capped), stable
  scope-qualified item ids, `HistorySearchRequest`/`HistorySearchResponse` with
  bounded cursors, and the optional enrichment seam: `EnrichmentProvider`,
  `EnrichmentSession`, `RequestBudget`, `EnrichmentBudgets`, `EnrichmentReport`
  and the repository-scoped `HostCache` (ETag-cached JSON under the repo scope;
  permission denial invalidates the whole cache, fail closed).
- `crates/repoise-core/src/adapter/git.rs`: `HistoryProvider` for Git —
  first-parent commits within the horizon (`git log` with unit/record
  separator fields), bounded changed-path summaries (`--name-only`), optional
  bounded hunk descriptors (`git show --format= --unified=0`), explicit
  shallow-clone and horizon gaps; empty repositories yield an empty lane.
- `crates/repoise-core/src/store.rs`: `history_item` + FTS5 `history_fts`
  published in the same generation transaction (schema v4, additive
  migration); history rows are retained per generation and removed by the
  same retention rules as chunks.
- `crates/repoise-core/src/indexing.rs`: when `history.enabled`, collects and
  optionally enriches the history set before transactional publication;
  `IndexOutcome` carries a `HistorySummary`.
- `crates/repoise-core/src/config.rs` and `schemas/repoise-config.schema.json`:
  opt-in `history` block (`enabled` default false, `horizon` 500,
  `maxPathsPerCommit` 20, `diffHunks` false) and `history.enrichment`
  (`host`, `tokenEnv`, budgets); doctor validates the budgets.
- `crates/repoise-cli/src/main.rs`: `search --lane history` (separate lane;
  never mixes with current chunks) and `read` rejection of `--lane history`.
- `crates/repoise-cli/src/github_enrichment.rs` (behind the default
  `github-enrichment` feature, `ureq`): read-only GitHub transport — verifies
  commit-to-PR hints through `GET /repos/{owner}/{repo}/commits/{sha}/pulls`
  (never infers from the message), fetches one verified change request
  (`title`, bounded `body`, `state`, permalink) ETag-cached through the
  session's host cache, with per-build request budgets and
  rate-limit/permission status classification (403 +
  `x-ratelimit-remaining: 0` or 429 → rate limited).
- Search lane: FTS5 BM25 over message/revision/paths/host metadata with
  per-term field matching, path filtering, candidate cap and bounded cursors;
  GitHub permalinks only for validated `github.com/owner/repo` remotes with
  full 40-hex `git:` revisions.

Verification performed: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets --locked -- -D warnings`,
`cargo test --workspace --locked` and `bash scripts/check.sh` (rustdoc) all
pass. Core unit tests cover hint parsing, permalink validation, item ids,
host-cache round-trip/invalidation and the enrichment session (verified
association, no association, rate limit stop, permission denial fail-closed
with cache invalidation, request/PR budgets, other-failure continuation,
foreign-host and missing-remote skips); CLI tests cover payload parsing,
status classification and session gating. A live smoke test indexed a scratch
Git repository with `history.enabled` and searched the history lane.

## Scope

- Opt-in, offline-capable local Git history lane.
- Optional verified GitHub PR enrichment (read-only API), disabled by default.

Out of scope: other hosts (deferred), crawling all issues/PR comments, embedding every
patch or full revision by default.

## Local history (master plan section 9)

- Default history preset: mainline commits, a configurable horizon (initial 500
  commits), and bounded changed-path summaries.
- Record horizon/shallow-clone gaps explicitly.
- Include commit message, parents, changed paths, and optional bounded diff hunk
  descriptors; do not embed every patch/full revision by default.
- History search is a separate lane or explicit filter, so old code does not pollute
  current search.
- History is a separate logical lane in the shared store; history is not required for
  the offline docs baseline.

## History item record (master plan section 6)

| Record | Required fields |
| --- | --- |
| History item | adapter-qualified revisionId, optional parents, affected paths, bounded summary; optional verified host/change-request association |

- Use adapter-qualified opaque revisions; never assume every revision is a 40-character
  hash or every change request a PR. Store hosting fields in optional namespaced
  metadata.
- Return GitHub permalinks only from a validated GitHub remote and exact SHA/path/
  range; absent one, return repoId/path/revisionId, not a guessed URL.

## GitHub enrichment (master plan section 9)

- Recognize commit-message PR references as unverified hints.
- GitHub enrichment optionally calls read-only APIs to verify commit-to-PR
  association and fetch title/body/review discussion under strict limits.
- Cache ETag/cursors; handle pagination, rate limits, deleted PRs and permission loss.
  Do not crawl all issues/PR comments implicitly.
- Expose provenance, fetched time, edited state, and remote coverage.
- PR text is historical intent, not current implementation proof.

## Credentials and privacy

- Use already configured read-only credentials through a provider adapter; never ask
  the agent to read a token file or put tokens in config committed to Git.
- Remote enrichment is disabled by default. A missing credential does not stop local
  indexing; local operation must work without credentials.
- Disabling/removing a repo must invalidate its served data; remote revocation must
  fail closed before serving refreshed remote content.
- Existing cached private content requires an explicit retention/access policy.

## Acceptance criteria (card K5)

- Shallow/horizon gaps reported explicitly.
- Commit-to-PR association verified, not inferred from commit message alone.
- Pagination, rate-limit and permission-failure behavior tested.

## Verification

Card-level verification: ambiguous PR hints, verified association, remote
denial/rate limits, private cache policy, edited/deleted comments, missing commit
history, and local operation without credentials.

Remote enrichment tests use fake/recorded API responses; no arbitrary production
endpoint access is needed.

## Rollback and limitations

History is opt-in config; disabling it removes the lane without affecting docs/code
search. Cached remote content is purged with the repo scope. Limitation: enrichment is
GitHub-only in v1.
