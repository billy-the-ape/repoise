## Scope

- Install a pinned repoise release in ai-gateway; no indexer implementation belongs in
  ai-gateway.
- Commit a reviewed `repoise.config.json` and optional approved scripts/overlay in
  ai-gateway; the overlay points at the installed package rather than copying
  implementation into the consuming repository.
- Add separate opt-in commands/config in ai-gateway; never change `pnpm rag:index`.
- Run the pilot: compare docs-only, docs+code lexical, and docs+code hybrid (master
  plan section 5) with the PR 6 evaluation harness; collect token/task data
  (rollout step 2).

Out of scope: any change to the Home Lab RAG contract, gateway chat orchestration,
background daemon installation without an explicit operator action, or publishing
repoise (a separately authorized release action).

## Boundary rules (master plan sections 1, 2, 10)

- ai-gateway consumes a pinned release. The pilot may use the same OpenAI-compatible
  embedding endpoint via Repoise's independent provider adapter and separate
  configuration.
- Do not import gateway configuration, database stores, chat orchestration, or Home
  Lab paths into the standalone core; this PR must not route gateway data into
  repoise config either.
- `pnpm rag:index` (Home Lab CLI) stays unchanged. Gateway route-attached context
  (`profiles.ts`) and capability operations (`capabilities.ts`) are optional future
  adapter points, not part of this PR.
- No schema migration to gateway.sqlite. A hosted capability is a later optional
  adapter, not a prerequisite for local agents.
