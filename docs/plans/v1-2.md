## Scope

- Optional embedding provider adapter (OpenAI-compatible endpoint) behind a versioned
  interface; the offline lexical baseline must remain complete without it.
- Content-addressed embedding cache and compatible profile handling.
- Incremental hybrid search with budgets, coverage reporting and lexical degradation.
- Evaluation of an optional built-in local inference preset (evaluation, not a ship
  commitment).

Out of scope: local history (PR 5), code grammars (PR 4), MCP/watch (PR 6).

## Provider adapter and security

- Endpoint/model settings are operator-selected; there is no mandatory cloud provider.
  Secrets resolve only via environment references; never ask the agent to read a token
  file or put tokens in config committed to Git.
- Before enabling a remote provider, explain what source/query content leaves the
  machine and configure budgets.
- A missing credential does not stop local indexing. Remote revocation must fail closed
  before serving refreshed remote content.
- Embed with bounded batching, timeouts, retry/backoff, cancellation, and request/input
  budgets. Pending/failed semantic chunks must not serve vectors for replaced text;
  report vector coverage and use lexical fallback. Never silently replace successful
  vectors with zeros.
- Vector jobs publish only if their expected scope/content/config hashes still match;
  discard superseded work.
- A pilot may use the same OpenAI-compatible embedding endpoint via an independent
  provider adapter and separate configuration; do not import gateway configuration,
  database stores, chat orchestration, or Home Lab paths into the standalone core.

## Caching and profiles (master plan sections 3, 6, 7)

- Content-addressed embedding cache identity uses normalized embedding input plus the
  full embedding fingerprint (provider/model revision or operator artifact ID,
  dimension, profile/tokenizer version).
- A rename may reuse vector input only when contextual path input has not changed.
- Reuse unchanged embeddings from the cache. Embeddings are indivisible per chunk
  input: regenerate only chunks whose complete input hash or provider/profile
  fingerprint changed. Never patch a vector by embedding just edited lines.
- Separate vector collections by model/profile/dimension; never compare incompatible
  spaces. Validate dimensions and vector finiteness before publication.
- Start with vectors in SQLite (bounded exact cosine for small indexes) behind a
  vector-store interface. Add an ANN/store adapter only when measured latency/memory
  justify it; do not require a service for a few thousand documents.
- The shared embedding cache lives at `repoise/repos/<repoId>/embedding-cache/`,
  isolated within the repository/access scope. Committed generations may reuse
  compatible repository-local vectors without serving another worktree's dirty text.
- Retention/GC must reference-count shared embeddings and preserve active
  readers/generations.

## Hybrid search (master plan section 8)

- Fuse independent rankings with reciprocal rank fusion (initial k=60, configurable),
  not raw addition of incomparable scores. Fuse per-corpus/profile ranked lists, not raw
  similarity values. Cross-corpus queries return a bounded mix; path/symbol intent and
  explicit filters control routing.
- Search response reports retrievalMode and lexical/vector coverage; search exposes
  pending paths and last scan time. Strict freshness performs reconciliation or fails
  clearly without implicitly calling remote providers.
- Expected-hash exact reads remain mandatory even when status reports healthy.
- Enforce maxOutputTokens server-side in addition to client budgets; deterministic tie
  ordering; cursors bind to filters/scope/generation and expire.
- Reranking remains optional and disabled unless measured benefit and budget justify
  it.

## Optional built-in local embeddings (master plan section 11)

- Evaluate an optional Rust local-inference adapter (ONNX Runtime bindings, e.g. `ort`,
  or a compatible Rust runtime) with a pinned small compatible sentence-embedding
  model, correct pooling/normalization/query prefixes/tokenizer and licensed assets.
  CPU is the baseline; GPU acceleration is optional. Benchmark prose and code
  separately rather than assume a small text model is a good code model.
- Provide zero-provider-configuration as an explicit local preset: the package selects
  a tested default artifact, exposes expected download/disk/RAM cost, and acquires it
  only on an explicitly requested setup command. A first download is network-dependent
  even though all subsequent inference is local. Support pre-provisioned model
  directories and strict offline mode that disables remote fetches. Missing assets
  produce actionable lexical fallback. No hidden npm postinstall/first-search downloads
  or unrequested telemetry.
- Index and query use identical pinned model/profile fingerprints. Optional dependencies
  and model caching must preserve a small lexical installation and avoid repeated
  downloads per consuming repository. Shared model artifacts contain no private corpus;
  source/vector caches remain scoped.
- Model choice, dimensions/weight precision, runtime versions, platform support and
  release license are evaluated during this card, not promised by the plan. Include
  local model bytes and query cold-start time in benchmarks. A built-in model removes
  provider setup, not inference/storage cost.
- Benchmark optional fp16 or int8 vector storage against float32 as an experiment: the
  theoretical component storage is 2x/4x smaller respectively, excluding scale
  metadata and any retained full-precision copy. Distinguish stored-vector
  quantization from embedding-model weight quantization. Reduced dimensions require a
  model-supported method or validated projection and matching query profile; arbitrary
  truncation is not acceptable. Compression is optional optimization, not a blocker for
  the first offline CLI milestone.

## Acceptance criteria (card K3)

- No re-embedding of unchanged input (cache hit by input hash plus full fingerprint).
- Dimensions and vector finiteness validated before publication.
- Lexical degradation: missing provider, timeouts, and partial batches fall back
  lexically with explicit coverage status.
- Token caps and output budgets enforced.
- p95 warm search <= 500 ms lexical and <= 2 s hybrid (remote embedding request reported
  separately) per the adoption gates.

## Verification

Card-level verification: provider timeout/partial batch, cancellation/retry cap,
profile/model changes, NaN/wrong-size vectors, lexical-only search, deterministic
ties, cursor/filter binding and output truncation. Add semantic runs to the section 11
benchmark matrix (warm/cold, memory, recall) for prose and code separately.

Commands (Linux/macOS; Windows uses `scripts/check.ps1`):

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
bash scripts/check.sh   # adds rustdoc with -D warnings
```

Contract tests need no arbitrary production endpoint/GPU access: use deterministic fake
or local providers in tests. Optional inference/platform features need their own
relevant tests, not blind --all-features runs.

## Rollback and limitations

Disabling the provider in config returns full lexical operation; pending/failed
semantic chunks never serve stale vectors, and superseded vector work is discarded.
Limitation: hybrid quality depends on the operator-selected model/profile; the section
11 gates decide promotion.
