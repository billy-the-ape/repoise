## Implemented state

- `crates/repoise-core/src/history.rs`: local history contracts and services.
  `HistoryProvider` (adapter seam), `HistorySet`/`HistoryItem`/`HunkDescriptor`
  records, PR-hint parsing (`#123` boundaries, deduped, capped), stable
  scope-qualified item ids, `HistorySearchRequest`/`HistorySearchResponse` with
  bounded cursors, and the optional enrichment seam: `EnrichmentProvider`,
  `EnrichmentSession`, `RequestBudget`, `EnrichmentBudgets`, `EnrichmentReport`
  and the repository-scoped `HostCache` (ETag-cached JSON under the repo scope;
  permission denial invalidates the whole cache, fail closed).
- `crates/repoise-core/src/adapter/git.rs`: `HistoryProvider` for Git. The mainline
  revision list comes from `git rev-list --first-parent` (trusted; used to map and
  bound records), and commit records come from a NUL-framed `git log -z
  --name-only` stream whose headers are prefixed with `\x01` plus a per-invocation
  random nonce — repository content predates the call, so it cannot contain the
  nonce: a path that merely looks like a framing header (control bytes, a 40-hex
  sha, `\x1f` bytes) is treated as a path, never a record, and control
  characters in messages or paths cannot shift another commit's fields. Changed
  paths are bounded per commit; optional bounded hunk descriptors come from
  `git diff-tree` (with `--root` against the empty tree for root commits, a
  tree diff against the first parent for merges); explicit shallow-clone and
  horizon gaps; empty repositories yield an empty lane.
- `crates/repoise-core/src/store.rs`: `history_item` + FTS5 `history_fts`
  published in the same generation transaction; schema v5 is additive — the
  `generation` row carries the history item count and a `history_meta` JSON
  column persisting the lane coverage/enrichment summary (also present in the
  base schema for new databases). History rows are retained per generation and
  removed by the same retention rules as chunks.
- `crates/repoise-core/src/indexing.rs`: when `history.enabled`, collects and
  optionally enriches the history set before transactional publication; scopes
  whose adapter has no history provider record an explicit `Unavailable` gap
  (empty lane, not a failure); the lane summary is persisted as `history_meta`
  with the generation; `IndexOutcome` carries a `HistorySummary` (including
  unattempted items).
- `crates/repoise-core/src/config.rs` and `schemas/repoise.config.v1.schema.json`:
  opt-in `history` block (`enabled` default false, `horizon` 500,
  `maxPathsPerCommit` 20, `diffHunks` false) and `history.enrichment`
  (`host`, `tokenEnv`, budgets); `tokenEnv` is required and must be a valid
  environment variable name (enforced by the schema and by doctor validation).
- `crates/repoise-cli/src/main.rs`: `search --lane history` (separate lane;
  never mixes with current chunks) and `read` rejection of `--lane history`.
- `crates/repoise-cli/src/github_enrichment.rs` (behind the default
  `github-enrichment` feature, `ureq`): read-only GitHub transport — verifies
  commit-to-PR hints through `GET /repos/{owner}/{repo}/commits/{sha}/pulls`
  (never infers from the message), fetched once per commit with bounded
  pagination (`per_page=100`, at most 10 pages, first page ETag-cached through
  the session's host cache) and matched against all hints; fetches the single
  verified change request (`title`, bounded `body`, `state`, permalink)
  ETag-cached, with per-build request budgets and rate-limit/permission status
  classification (primary: 403 + `x-ratelimit-remaining: 0` or 429; secondary:
  403/429 + `Retry-After` → rate limited, stops the pass without wiping the
  cache). A missing or empty credential disables enrichment entirely (no
  unauthenticated requests are ever sent) and local indexing is unaffected.
- Search lane: FTS5 BM25 over message/revision/paths/host metadata; every query
  term is parenthesized so multi-word queries require each word in the same
  record (AND semantics per term across fields), and the path filter matches
  each recorded path individually through the FTS5 `GLOB` operator (never a
  `LIKE` over the whole JSON blob). The response carries the persisted lane
  coverage (`HistoryLaneStatus`: enabled, item count, head revision, gaps,
  enrichment outcome) so empty pages still report coverage; items skipped by
  a budget or early stop are counted as unattempted. `status` reports the same
  lane state from the published generation.
- Lane status and untrusted-content handling: enrichment sessions gate on the
  provider's exact remote host (`github.com`, never prefix lookalikes such as
  `github.acme.corp`), and host-provided titles/bodies pass through secret
  redaction before storage; verified associations store the host `updated_at`
  timestamp (`updated_at_ms`) alongside the fetch time.

## Scope

- Opt-in, offline-capable local Git history lane.
- Optional verified GitHub PR enrichment (read-only API), disabled by default.

Out of scope: other hosts (deferred), crawling all issues/PR comments, embedding every
patch or full revision by default.

## Local history (master plan section 9)

- Default history preset: mainline commits, a configurable horizon (initial 500
  commits), and bounded changed-path summaries.
- Record horizon/shallow-clone gaps explicitly.
- Include commit message, parents, changed paths, and optional bounded diff hunk
  descriptors; do not embed every patch/full revision by default.
- History search is a separate lane or explicit filter, so old code does not pollute
  current search.
- History is a separate logical lane in the shared store; history is not required for
  the offline docs baseline.

## History item record (master plan section 6)

| Record | Required fields |
| --- | --- |
| History item | adapter-qualified revisionId, optional parents, affected paths, bounded summary; optional verified host/change-request association |

- Use adapter-qualified opaque revisions; never assume every revision is a 40-character
  hash or every change request a PR. Store hosting fields in optional namespaced
  metadata.
- Return GitHub permalinks only from a validated GitHub remote and exact SHA/path/
  range; absent one, return repoId/path/revisionId, not a guessed URL.

## GitHub enrichment (master plan section 9)

- Recognize commit-message PR references as unverified hints.
- GitHub enrichment optionally calls read-only APIs to verify commit-to-PR
  association and fetch title/body/review discussion under strict limits.
- Cache ETag/cursors; handle pagination, rate limits, deleted PRs and permission loss.
  Do not crawl all issues/PR comments implicitly.
- Expose provenance, fetched time, edited state, and remote coverage.
- PR text is historical intent, not current implementation proof.

## Credentials and privacy

- Use already configured read-only credentials through a provider adapter; never ask
  the agent to read a token file or put tokens in config committed to Git.
- Remote enrichment is disabled by default. A missing credential does not stop local
  indexing; local operation must work without credentials.
- Disabling/removing a repo must invalidate its served data; remote revocation must
  fail closed before serving refreshed remote content.
- Existing cached private content requires an explicit retention/access policy.

## Acceptance criteria (card K5)

- Shallow/horizon gaps reported explicitly.
- Commit-to-PR association verified, not inferred from commit message alone.
- Pagination, rate-limit and permission-failure behavior tested.

## Rollback and limitations

History is opt-in config; disabling it removes the lane without affecting docs/code
search. Cached remote content is removed when the repository scope is purged
(`purge --all`); a worktree-scoped purge leaves the repository-scoped host cache
in place, and disabling `history.enrichment` does not delete it. Limitation:
enrichment is GitHub-only in v1.

## Deferred (explicit)

Scope the card lists that this PR does not implement, recorded as deferred rather
than silently omitted:

- Review-discussion fetch ("fetch title/body/review discussion under strict
  limits"): only title/bounded body/state/permalink are fetched; discussions
  remain out of scope in v1.
- Edited-state exposure ("Expose ... edited state"): the association stores the
  host `updated_at` timestamp but no explicit edited flag.
- Explicit deleted-PR handling and test: a 404 for a change request is a
  per-item failure (`Other`), leaving the hint unverified; the revocation-vs-
  deleted case is documented in the status classification, with no dedicated
  fixture yet.
- Private-cache retention/access policy: the host cache is plaintext JSON under
  the cache root with default permissions; a retention/access policy for cached
  private content is not written.
- Card verification items "edited/deleted comments" and "private cache policy":
  follow the two deferrals above.

Completed in this PR against the card: pagination (bounded per-commit page
walk with `Link` headers, tested end to end against a fake host), primary and
secondary rate-limit classification and tests, permission-failure
fail-closed with cache invalidation, and local operation without credentials
