## Final state (implemented)

- `crates/repoise-core/src/chunk/code.rs` owns the pinned offline tree-sitter grammars
  (`tree-sitter-typescript` 0.23.2 with TSX, `tree-sitter-javascript` 0.25.0 for
  JS/JSX/MJS/CJS) and the deterministic line-window fallback for every other code
  language (`code-line/1`); `parse_code(language, text)` is the single dispatch.
- Code files index to the `code` corpus: structural units (exports, functions, methods,
  classes, interfaces, enums, type aliases, modules) with exact 1-based line ranges,
  enclosing scope/symbol context and labeled oversized splits; the TSX superset grammar
  handles JSX, decorators and all TS/TSX syntax so parser errors are expected to be
  rare and are recorded per range, never dropped.
- Symbols publish per generation (`symbol` table): kind, line range, parent symbol,
  export flag and the covering chunk; chunk rows carry the primary symbol for FTS.
- Reference edges publish per generation (`reference` table): import bindings resolve
  against the generation's file set (certain confidence with target symbol when the
  target exists; uncertain otherwise); unqualified calls/references are bounded hints
  resolved locally first, then through import bindings, with honest confidence labels.
  No type resolution or call graph.
- `chunk_fts` gains `symbol` and `context` columns (the table rebuilds in place during
  the additive, idempotent v3 migration when it predates `context`).
- Embedding scope (`embedding.scope`: `docs` default, or `docs+code`; the hybrid preset
  defaults to `docs+code`) selects which corpora receive vectors; scope enters the
  generation record and the chunker fingerprint.
- `repoise index` reports code symbol and reference-edge totals; incremental rebuilds
  reparse only changed code files and re-resolve edges against the new generation.
- Acceptance fixtures live in `crates/repoise-core/tests/v1_4.rs` (grammar chunks,
  symbol/export/parent shape, import/call edge resolution, FTS reachability, line
  fallback without symbols, reuse and repair); grammar-level behavior fixtures live in
  `chunk/ts.rs` tests. Benchmarks (code ablation, build/memory cost) remain pending in
  the section 11 matrix.

## Scope

- Optional code corpus with Tree-sitter grammar adapters for TypeScript/JavaScript.
- Symbol extraction, structural chunks, code-oriented lexical fields, reference hints.
- Generic line-window fallback for unsupported languages with honest coverage labels.
- Release the recommended docs+code lexical preset when this card passes.

Out of scope: compiler-grade call graph, generated LLM summaries in the index, semantic
code vectors (opt-in via PR 3 profiles), compiler/LSP enrichment adapters (future).

## Grammar and parsing (master plan sections 3, 5)

- Use Tree-sitter grammar adapters initially for TypeScript/JavaScript; extend via
  pinned language plugins (for example Python) only with fixtures. Pin grammar/query
  versions. Syntax plugin contracts are versioned Rust interfaces, not an unsafe
  arbitrary shared library ABI or a promise of third-party hot loading. Candidate
  binding: the tree-sitter Rust crate; validate versions, licenses, native assets and
  platform support before adoption.
- Generic line-window fallback keeps unsupported languages usable and labels parsing
  coverage honestly. Optional semantic enrichments cannot make generic indexing
  unavailable.
- Record parser errors; fall back for affected ranges rather than dropping the whole
  file.
- Language detection must not require package.json, tsconfig, src/, or a particular
  framework; it must work on mixed-language repos and docs-only folders.
- Do not block async executors with CPU-heavy parsing; use bounded worker scheduling.

## Chunking (master plan section 5)

- Chunk at function/method/type/class/module boundaries. Include attached doc comments,
  signature, enclosing symbol, decorators, and relevant import names in compact
  embedding context.
- Split large functions by statement/block boundaries while retaining parent/
  signature.
- Do not embed an entire dependency closure or repeat whole imports in every read.
- Code uses language-aware symbols/signatures/blocks and code-oriented lexical fields;
  keep corpus role, parser/chunker versions, coverage, and retrieval weights distinct
  from docs/config. The shared persistent store and unified search interface query both
  logical indexes.
- Avoid generated LLM summaries in the initial index: they increase build cost and can
  introduce unsupported claims.

## References (master plan section 5)

- Build declaration/export/import links and local reference hints. Syntax alone does not
  resolve dynamic dispatch or prove a call graph; label uncertain edges. Compiler/LSP
  enrichments are optional future adapters.
- Definitions, related tests, imports, and parent scopes are bounded related results,
  fetched on demand (the `related_project_knowledge` operation ships with PR 6). Rank
  implementation and tests distinctly.

## Vectors (opt-in, via PR 3)

- The recommended preset disables code vectors; semantic code vectors are a separate
  opt-in.
- Benchmark a code-capable embedding model against the available text model; separate
  profiles/collections when needed. Choose based on recall/cost, not branding.

## Presets and pilot comparison (master plan sections 5, 11)

- Presets: docs-only, docs+code lexical (recommended default once this card passes),
  hybrid (docs vectors optional; code vectors opt-in).
- For the ai-gateway pilot compare docs-only, docs+code lexical, and docs+code hybrid.
- Code vectors ship enabled in the pilot only if they improve code-query recall@5 by at
  least 10 percentage points over code lexical at an acceptable measured build/memory
  cost.

## Benchmarks (master plan section 11)

- Add code runs to the section 11 benchmark matrix after this PR: code behavior

## Acceptance criteria (card K4)

- TS/JS and fallback fixtures pass with honest coverage labels.
- Parser errors handled per range; files are not dropped.
- Enclosing scope parents recorded on chunks.
- Code ablation (docs-only vs docs+code lexical) measured.

## Verification

Card-level verification: overloaded/nested/large symbols, imports/comments/decorators,
invalid code, unsupported grammars, test relationships, and honest uncertainty of
reference edges. Rust self-hosting fixtures exercise the code path on this repository.

Commands (Linux/macOS; Windows uses `scripts/check.ps1`):

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
bash scripts/check.sh   # adds rustdoc with -D warnings
```
